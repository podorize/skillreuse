# 2. Related work

This study draws on three lines of work: software reuse, agent skills, and good practices for machine learning on mined data.

Software reuse has long been studied as the adoption of components and the spread of solutions across open-source projects \cite{mockus2002two,haefliger2008code}. Large analyses of GitHub showed that duplicated files are everywhere \cite{lopes2017dejavu}, and that code is reused through dependencies, copy-and-paste and templates \cite{heinemann2011extents}. Like these studies, we find copies by comparing the exact content of files. Unlike them, the copied artifact is natural language, and we follow each copy in time and by account, to tell real adoption by other developers apart from self-copying and bulk collection.

Research on language models using tools has focused on how a model selects and invokes those tools \cite{schick2023toolformer,shen2023hugginggpt,yao2023react,qin2023toolllm}.
Agent skills, in contrast, are persistent, human-readable files stored in repositories \cite{agentskills_spec}.
GitSkills offers the first large collection of them \cite{gitskills2027}.
Recent studies examine barriers to skill reuse \cite{zhang2026keepskillsreuse}, test whether skills help agents solve real tasks \cite{han2026sweskillsbench}, and track prompt evolution within software projects \cite{tafreshipour2025prompting}. To our knowledge, however, no study has examined whether skill text predicts adoption by other developers.

With mined data, when related examples, such as files from the same account, appear in both the training and the test data, a model can memorize the group instead of learning a general relation \cite{kaufman2012leakage}. The usual remedy is to split the data by group \cite{saeb2017need,roberts2017cross}. Models can also exploit accidental patterns that happen to correlate with the target \cite{geirhos2020shortcut,lapuschkin2019unmasking}; in mined datasets, such patterns can come from the way the data were collected. Comparing models over repeated cross-validation needs a correction for the overlap between training sets \cite{nadeau2003inference} and, when many comparisons are made, for multiple testing \cite{holm1979simple}. To interpret a model, permutation importance measures how much its performance depends on each attribute \cite{breiman2001statistical,molnar2020interpretable}, and SHAP values split each prediction into the contributions of the attributes \cite{lundberg2017unified,lundberg2020local}. Both describe the model, not the world \cite{shmueli2010explain}, and we use them in that sense.
